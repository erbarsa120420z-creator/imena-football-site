# ИМЕНА — Football Lab с автоматическим обновлением

## Как запустить на компьютере

Требуется Python 3.10+ и интернет.

### macOS / Linux
```bash
cd imena-football-site
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

### Windows
```powershell
cd imena-football-site
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
py -m pip install -r requirements.txt
py app.py
```

Открой в браузере: http://127.0.0.1:5000

## Обновление данных
- При первом запуске приложение автоматически попробует получить данные.
- Кнопка **«Обновить с сайта»** повторно скачивает заявку команды, агрегированную статистику игроков и календарь турнира.
- Интерфейс проверяет локальный API каждые 5 минут; backend обновляет данные с сайта лиги, если сохранённый снимок старше 30 минут.
- Успешный снимок сохраняется в `data.json`, чтобы сайт мог показывать последние данные, если сайт лиги временно недоступен.
- Фото профилей игроков, если доступны, берутся с публичных страниц лиги.

## Что собирается
- Игроки из заявки команды: имя, амплуа, матчи, голы, передачи, жёлтые/красные карточки, ID и фото.
- Все найденные завершённые матчи команды в календаре выбранного турнира: дата, соперник, счёт за/против.

## Важные ограничения
- Это парсер публичных страниц, не официальный API. Если лига поменяет HTML-разметку, парсер может потребовать обновления.
- Не обходятся логины, CAPTCHA или технические ограничения. Частые запросы не нужны; обновляй данные вручную по необходимости.
- Статистика событий, которой лига не публикует (удары, потери, отборы, минуты на поле), автоматически появиться не сможет.
- Для размещения сайта в интернете нужен сервер/хостинг, где можно запускать Python. Один статический Netlify-сайт не сможет выполнять этот Python-скрейпер без отдельного backend/cron job.


## Карточки недели

В навигации есть страница «Карточки недели» только для состава «Имена». Она показывает рейтинг 82–90 за последние 7 дней, голы, ассисты и матчи. Фото берётся с профиля игрока на сайте лиги; если фото отсутствует или не загружается, карточка показывает `GOAT`.

Важно: недельные показатели собираются из строк матчевой статистики в профилях игроков. Если сайт лиги не отдаёт такие строки или изменит HTML, карточка не будет подменять недельные показатели сезонными — игрок останется с базовым рейтингом 82 и нулём за период до исправления парсера.


### Фотографии игроков

При обновлении программа проверяет портреты в профилях игроков лиги: `src`, lazy-load атрибуты, `srcset`, ссылки на оригинальные изображения, `og:image` и CSS background. Если профиль временно недоступен, ранее найденное фото сохраняется. Если портрета нет, на странице «Карточки недели» показывается `GOAT`. В строке статуса после обновления выводится сводка найденных, сохранённых и отсутствующих фотографий.

## Тактический помощник

Страница «Тактика и схемы» включает пять вариантов расстановки для 6×6 с вратарём: 2–2–1, 1–3–1, 2–1–2, 3–1–1 и 1–2–2. Можно выбрать игровой план (баланс, прессинг, контратаки, удержание преимущества или отыгрыш), соперника из календаря и вручную назначить вратаря.

Программа формирует предварительную основу из пяти полевых игроков, учитывая голы, передачи, количество матчей и соответствие указанному амплуа. При обновлении данных с сайта лиги рекомендации пересчитываются. Совет по сопернику основан только на сохранённых результатах «Имен» против него, если такие матчи есть.

Это эвристическая рекомендация, не полноценная модель тренера: публичные данные не содержат гарантированной информации о доступности игроков, игровой форме, минутах на поле, усталости, отборах и потерях. Вратарь не назначается автоматически, потому что его позицию нельзя надёжно вывести из сезонной статистики. Перед матчем проверьте состав и скорректируйте основу вручную.


## Новые разделы: мини-игра, цели и чемпионат

- **Мини-игра «Пенальти за Имена»**: выбери игрока, пробей серию из пяти ударов и сравни рекорд. Локальный зал славы хранится только в браузере на этом устройстве; это развлечение, а не официальная статистика.
- **Турнирная таблица**: позиции и очки берутся с основной страницы 7-го сезона; дополнительные показатели (победы, ничьи, поражения, забитые/пропущенные) дополняются подробной таблицей, только если число сыгранных матчей совпадает, чтобы не смешивать разные туры.
- **Бомбардиры всей лиги**: рейтинг берётся с публичной страницы статистики турнира, с голами, матчами и голами за матч.
- **Цели сезона**: сайт определяет текущую позицию, разницу в очках с соседними командами и возможный максимум очков исходя из оставшихся матчей регулярной части (9 туров). Дополнительно предлагает игровые цели: уменьшить количество пропущенных и стремиться к 3+ голам за матч. Это ориентиры, а не обещание конкретного места.

Ссылки источников: https://msk-6x6.ru/tournament/1065992, https://msk-6x6.ru/tournament/1065992/tables, https://msk-6x6.ru/tournament/1065992/stats. Парсер работает с публичными страницами и может потребовать обновления при изменении их разметки.


### Проверка фотографий (обновление)
Парсер проверяет профиль каждого игрока из актуальной заявки и отбрасывает стандартную картинку-заглушку лиги. В статусе обновления показываются найденные фото и имена нескольких игроков без опубликованного портрета. В карточках и выборе персонажа вместо одинакового силуэта показываются инициалы, если настоящего фото нет. Это не создаёт и не подменяет реальные лица: чтобы фото появилось, оно должно быть загружено в профиль игрока на сайте лиги. После этого нажмите «Обновить с сайта».


### Фирменные материалы клуба
В `assets/` добавлены присланные командой эмблема, домашняя форма и фотографии команды. Они используются прямо в интерфейсе сайта. Если вы переносите сайт на другой хостинг, сохраняйте папку `assets` рядом с `index.html`.


### Портреты игроков
В `assets/players/` сохранены 10 присланных портретов. В `index.html` есть сопоставление имени игрока с файлом для карточек/выбора персонажа, а также отдельная сетка портретов на главной странице. Если имя на сайте лиги написано иначе, поправьте ключ в `CLUB_PLAYER_PHOTOS`.


### Обновление карточек игроков
Сопоставление портретов применяется через `clubPhotoForPlayer()` в общем рендерере аватаров, включая карточки состава и выбор персонажа. Если имя в данных лиги отличается, функция также проверяет обратный порядок имени и фамилии.


### Публикация сайта для нескольких устройств

Проект подготовлен к развёртыванию на Render: в корне есть `render.yaml`, приложение использует `PORT`, а снимок данных лиги можно хранить на подключённом диске. Чтобы опубликовать сайт, загрузите эту папку в свой GitHub-репозиторий и создайте Web Service на Render из репозитория. После успешного деплоя Render выдаст общую HTTPS-ссылку — её можно открыть с телефона и компьютера.

Важно: прогресс мини-игры сейчас хранится в `localStorage` браузера, то есть рейтинг персонажа и серии не синхронизируются между разными устройствами. Для общей таблицы рейтингов всем пользователям нужен отдельный серверный API/база данных и желательно авторизация. Этот архив настраивает публикацию и хранение снимка статистики, но не включает полноценную синхронизацию игрового прогресса между устройствами.


### Общая база данных для нескольких устройств

Добавлена SQLite-база `data/imena.sqlite3` (путь можно изменить через `IMENA_DB_PATH` или `IMENA_DATA_DIR`). При публикации на Render каталог `/opt/render/project/src/data` подключён как persistent disk, поэтому прогресс мини-игры сохраняется между перезапусками и виден всем телефонам/компьютерам, открывающим один и тот же адрес сайта.

API:
- `GET /api/game-data` — общий рейтинг персонажей и последние результаты;
- `POST /api/game/series` — сохранить завершённую серию пенальти и начислить XP;
- `GET /api/health` — проверить доступность приложения и базы данных.

База создаётся автоматически при старте приложения. Никаких ручных SQL-команд не требуется. Для совместного рейтинга все пользователи должны открывать один и тот же развёрнутый сайт. Сейчас это общий публичный рейтинг без аккаунтов: имя персонажа выбирается из списка команды, а отдельной идентификации пользователей и защиты от намеренного накручивания результатов пока нет. Для продвинутой версии можно добавить авторизацию и ограничение частоты запросов.
